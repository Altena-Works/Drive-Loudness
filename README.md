# DriveLoudness

Google Driveで動画を開くと自動で部分解析し、動画ごとの音量差を固定倍率で補正するChrome拡張です。適用時は動画上に補正dBだけを約3秒表示します。冒頭と全体の3秒区間を最大16地点測定します。再生中の音量追従やリミッターは使いません。

現在はMP4 / AAC-LC / mono・stereo向けの開発版です。OAuthクライアントの設定が必要です。直接音声経路は隔離Chromeで固定倍率・原音復帰を計測し、実Driveでも処理後に音声信号が出ることを確認しました。スピーカーからの実音圧の測定は行っていません。

## セットアップ

Node.js 22以降、npm、Chrome 116以降を使用します。

1. このフォルダーで依存関係を取得してビルドします。

   ```sh
   npm ci
   npm run build
   ```

2. Chromeの `chrome://extensions` でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」から、このプロジェクトの `dist` を選びます。表示された拡張IDを控えます。
3. [Google Cloud Console](https://console.cloud.google.com/)で使用するプロジェクトを選び、Google Drive APIを有効にします。Google Auth Platformの同意画面を設定し、個人開発のテスト中は自分のGoogleアカウントをテストユーザーに追加します。
4. OAuthクライアントを「Chrome拡張機能（Chrome Extension）」として作り、手順2の拡張IDを登録します。**クライアントシークレットは使いません。**
5. `config.example.json` を参考に、`config.local.json` を作り、作成した公開クライアントIDを設定します。

   ```json
   {
     "clientId": "123456789012-your-client.apps.googleusercontent.com"
   }
   ```

6. `npm run build` を実行し、Chromeの拡張一覧から再読み込みします。拡張の「設定」→「Googleに接続」から、自分でログイン・同意を行います。

同じ `dist` のパスを使い続けてください。別のパス・別PCへ移す場合は、拡張IDとOAuth登録を合わせる必要があります。既存の拡張公開鍵がある場合は `config.local.json` の `publicKey` に設定できます。秘密鍵は設定しないでください。

要求するスコープは `https://www.googleapis.com/auth/drive.readonly` だけです。Drive全体を読む権限ですが、実装は開いた動画の情報と部分データをGETするだけで、作成・変更・削除は行いません。このスコープはrestricted scopeに分類されるため、不特定多数への配布は個人テストとは別にGoogleの検証要件を確認してください。[Drive APIのスコープ](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)、[Chrome OAuthの設定](https://developer.chrome.com/docs/extensions/how-to/integrate/oauth)

ページ操作にはDrive・Docsのほか、Driveの動画本体が置かれる `youtube.googleapis.com` へのアクセス権を使います。同ホストでは `/embed/` かつ `ps=docs`・`origin=https://drive.google.com` のフレームに限り、動画の検出・一時停止・音量の保存と復元を行います。

## 使い方

1. Driveで動画を開くと、プレーヤーの準備後に自動で解析します。単独表示・フォルダー内プレビューに対応し、拡張ボタンを押す必要はありません。
2. 初回解析中は一時停止します。拡張ボタンから測定地点数と経過秒を確認できます。動画を特定できない場合は最大10秒で待機を解除します。解析は最大約1分で、終了通知が届かない場合も解析開始から65秒で未補正に戻ります。他の動画の解析を待つ時間は含みません。通常のDrive再生操作で視聴でき、適用時に `−1.9 dB` のような小さな表示が約3秒で消えます。Chromeが音声処理を再生待ちにした場合も、Driveの再生ボタンを使います。
3. 聞く音量は端末側で調整します。拡張は−23 LUFSの固定基準で動画間の差を補正し、追加の試聴音量調整は行いません。補正中はプレーヤー音量を100%に合わせます。
4. 原音で聞く場合は、拡張ボタンの画面右上にある一時停止アイコン（この動画の補正を停止）を押します。停止中や未補正のときは再生アイコン（補正を再開）で、同じ動画の自動処理を再開できます。停止すると一時停止し、次の通常再生は原音になります。
5. 別の動画を開くと自動で次の動画を解析します。左右切り替えでは表示中のプレーヤーだけを扱い、非表示の先読み動画は補正しません。親子の通信は接続済みのMessagePortを使い、遷移中の動画ウィンドウへ直接送信しません。解析中に切り替えても古い結果を適用しません。拡張が変更した音量・ミュートは停止時に復元し、途中でユーザーが変更した音量は維持します。

補正基準は−23 LUFS固定です。ポップアップと設定画面には音量調整スライダーを置きません。同じ内容の測定結果はブラウザ内に最大5000件・5MiBまで保存し、上限では測定日時が古い結果から整理します。Driveの動画リビジョンを優先し、取得できない場合は内容のチェックサム、最後にDriveの版番号で更新を判定します。Driveの通常の版番号は内部メタデータ更新でも変わるため、内容の版と区別しています。[Filesの各フィールド](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)

未対応・認証切れ・解析失敗の場合は小さく「未補正」と理由を表示します。認証画面を自動では開きません。認証切れは設定画面から接続し直してください。同名ファイルが複数あり表示動画を特定できない場合は、単独表示のURLを使用します。

「Googleに接続」にはChrome Identity APIを使用します。Driveで使っているアカウントと、拡張が読み取りできるアカウントのアクセス権を確認してください。

## フォルダーを一括解析する

拡張ボタンまたは設定画面の「フォルダーを一括解析」を開き、DriveのフォルダーURLまたはIDを指定します。Driveのフォルダー上で拡張ボタンから開くと、ボタンを押した時点のフォルダーIDを自動入力します。既存の一括解析画面を開き直す場合も更新しますが、対象確認中・解析中は進行中の対象を維持します。フォルダーを特定できない画面や設定画面から開いた場合は手動入力します。「対象を確認」でサブフォルダーを含む件数を確認してから、「解析を開始」を押してください。確認だけでは音声を取得しません。

新規解析・保存済み再利用・対象外・失敗の件数と、現在の動画の進捗を表示します。ショートカット先へは進みません。MP4以外の動画は対象外、MP4の非対応コーデックや取得失敗は失敗として表示し、次の動画へ進みます。アクセス権のないフォルダーや未完了の検索結果は、全件確認したものとして扱いません。

処理中は専用タブを開いておきます。他のタブへ移っても処理を続け、「中止」またはタブを閉じると未処理分を中断します。Chromeの終了・拡張更新後には自動再開しません。解析済み結果は残るため、同じ対象を確認して再度開始すれば保存済み結果を再利用できます。Google連携が回復しない場合は中断し、設定からの再接続を案内します。

通常の動画プレビューと解析Workerは1件ずつ共有します。一括処理の実行中の1件が終わると通常プレビューの解析を優先します。保存済みの動画プレビューはWorkerの空きを待たずに適用します。1件あたりの取得量・解析時間・補正方式は通常の解析と同じです。

対象確認は非フォルダー5000件・1000フォルダー・一覧5MiBまでです。上限に達した場合は、より狭いフォルダーを指定してください。実行中に追加された動画は次回の対象確認で扱います。追加のOAuth権限は使用せず、Driveへの書き込みも行いません。

## 処理と制約

- MP4の索引だけを読み、複数地点のAAC音声パケットをRange要求で取得します。映像は復号しません。索引は最大16MiBです。
- 取得は合計64MiB・256要求・60秒まで。Rangeを無視する200応答や範囲不一致を拒否し、全ダウンロードへ切り替えません。中断するとWorkerを終了します。
- 48秒超では冒頭0〜3秒を必ず測り、本編の分散区間と合わせて9→13地点、必要なら16地点まで追加します。追加前後で推定値が0.5 LU以内、短時間の補助指標が1 LU以内に安定したら適用します。自然な区間音量差だけでは拒否しません。最終でも推定が安定しない、無音、有効区間不足の場合は未補正にします。48秒以下では音声区間を連続して測定します。
- K-weighting、400msブロック、絶対・相対ゲートによって推定します。離れた区間を連結せず、各測定点が代表する時間でエネルギーを重み付けします。冒頭を特別に測ることで、全体平均への重みを過大にしません。**長い動画の間欠推定は、全編の厳密なIntegrated LUFSではありません。**
- 補正量は平均を目標へ揃える値を基本とし、本編の時間重み付き短時間音量P90と冒頭音量の大きい方が、目標＋6 LUを超えない固定ゲインを選びます。この6 LUは本拡張の初期調整値で、規格値や実音楽での聴感検証済みの値ではありません。静かな導入と大きな本編の相対差は維持します。
- 増幅上限は+20dBです。短時間音量による調整と増幅上限は区別して表示します。上限により目標へ届かない場合があります。瞬間ピークの制限や音割れ防止は行いません。
- 測定方式はanalyzer v2です。旧方式のキャッシュは新方式の判定に使わず、動画を開いた際に自動で再解析します。Google接続と既存データは維持します。以前の目標値・試聴音量の設定は削除せず適用対象から外します。
- 通常のMP4で、音声が1トラックのAAC-LC、mono/stereoに対応します。WebM、MOV、fragmented MP4、複数音声、複雑な編集リストは未対応です。対応形式でも予算を超える索引・配置の場合は終了します。
- 音声処理は動画要素へ直接固定ゲインを適用します。タブ音声取得の権限や毎回の拡張起動操作は使いません。同一originのURL・blob/MSEを対象にし、無音化する可能性のあるcross-originソースは接続前に拒否します。停止時は接続済みの経路を等倍に戻し、同じ要素の再利用でも二重接続しません。音声処理を起動できない場合、接続前なら原音を維持します。すでに接続済みの音声経路を再開できない場合は、ページの再読み込みを案内します。
- Driveの変換済み音声と原本の差、Drive UI変更、動画切替の全イベント順序、実音の遅延は、実機での確認が必要です。「推定補正」として扱ってください。

動画・PCM・OAuthトークンはディスクやログに保存しません。トークンはChrome Identity APIのメモリキャッシュと処理中のメモリで使います。解析結果は `chrome.storage.local`、動作状態は `chrome.storage.session` に保存します。外部の音声解析サービスは使用しません。

設定画面で測定結果を削除できます。「接続情報を解除」は拡張のトークンキャッシュと測定結果を消去します。Google側でのアプリ許可の撤回は、Googleアカウントの設定から操作してください。

## 開発と検証

```sh
npm run build
node scripts/fixtures.mjs
npm test
npx playwright install chromium
node tests/audio-path.mjs
npm run test:browser
npm run test:loudness
```

テストにはffmpeg・ffprobeが必要です。テスト用動画はリポジトリに含めていません。`node scripts/fixtures.mjs` を実行すると、人工音声のMP4を `tests/fixtures` に生成します。

- 単体テスト: Rangeの検証・上限・中断、MP4位置、既知信号、固定ゲイン、自動処理前の音声抑止、初回再生待ち、音量/ミュート復元、古い結果の拒否、タブ間の解析キュー、動画内容の更新判定。
- 音声経路テスト: 隔離Chromeで実際の動画音声を計測します。0.5倍の補正で実測0.50049倍、解除後は1.00113倍で元の音量へ復帰し、同一要素の二重接続防止とAudioContextの再開を確認しました。
- ブラウザテスト: ビルド済み拡張のコピーで自動解析、通常の再生操作、dB通知と消去、音声出力、原音復帰、キャッシュ、複数タブ、同一要素のソース更新、先読みiframeを残した左右往復・高速切替・Drive外側の再生ボタン・STOP後再生、版更新に加え、一括解析の階層・ページ送り・再利用・期限回収・画面終了時の中断を確認します。Google/OAuth通信だけをローカルデータに置換します。offscreen Workerの通信はPlaywrightのrouteで捕捉できないため、テスト用コピーだけにfetchの置換を前置します。元の配布物は変更しません。
- `test:loudness`: 静かな導入、大きい導入、強弱の繰り返し、無音導入、短尺、16地点での収束、未収束の人工AACを生成し、実WebCodecsの部分解析とffmpegの全編参照を比較します。結果は`test-results/loudness-v2/`へ保存します。ケース名を引数にすると対象だけ再実行できます。実音楽の聴感評価とは区別します。
- 実Driveの旧手動版では3本の推定値が基準−21.1、小音量−27.1、大音量−15.1 LUFSで、各8地点・約0.35 MiBを取得しました。最新の接続競合対策とUI変更を含む版の実Drive確認は未実施です。高画質・長時間ファイルとスピーカーの実音圧も未検証です。

ブラウザの取得先を分ける場合は、取得時とテスト実行時の両方で `PLAYWRIGHT_BROWSERS_PATH` を指定してください。生成物は `dist`、テスト用スクリーンショットは `test-results` に出力します。どちらもソースとは別です。

実装は `src/analysis`（取得・MP4・推定）、`src/extension`（認証・状態・音声経路）、`src/ui`（画面）に分かれています。

## アイコン

波形マークは白背景に濃い青（#244F6B）で描いています。元のSVGは`src/icons/icon.svg`、PNGは同じディレクトリの16・24・32・48・128pxです。通常のビルドで拡張アイコンとツールバー用に組み込みます。SVGをCanvasへ直接描画してPNGを生成します。再生成する場合は、PlaywrightのChromiumを用意して`npm run icons`を実行します。
